# FlowProbe

一款 Codex 桌面版风格的**多协议网络与串口调试台**。把日常调试最常用的连接、收发、Mock、接口测试集中到一个桌面应用里，统一的「连接 → 发送 → 接收 → 观察」工作流。

名字取自工具本身在做的事：报文在链路上流动（flow），工具在链路中间下一根探针（probe），把流过的每一帧截下来看清楚。图标就是这个意思——三条数据流线，中间一条在探针处断开。

界面文案是中文，但应用名、安装包名、窗口标题一律用英文 `FlowProbe`：这些字符串会进入文件系统路径、快捷方式、进程名与命令行，中文在这些位置容易碰上编码与转义问题。

> **从 1.18.0 及更早版本升级**：应用标识从 `debug-toolbox` 改成了 `flowprobe`，数据目录随之变化。首次启动会自动把旧目录里的会话、报文历史与自签证书复制到新目录（复制而非移动，旧版本仍可回退使用）。详见 [四、打包 → 改名与数据兼容](#改名与数据兼容)。

- 平台：Windows / macOS / Linux（当前打包目标为 Windows x64）
- 技术栈：Electron 31 + React 18 + TypeScript + Zustand，electron-vite 构建，electron-builder 打包
- 当前版本：**1.21.4**

应用采用「单窗口多会话」模式：每个连接是一个独立会话，可并行运行、互不干扰。左栏是会话列表与全局入口，中栏是报文时间轴与发送编辑器，右栏是当前会话的检查器。

## 二、功能详解

### 1. TCP 客户端 / 服务端

**客户端设置**：目标地址与端口、连接超时、断线自动重连（指数退避，见下）、Nagle 算法开关（noDelay）、KeepAlive、心跳（自定义内容与间隔，支持 TEXT/HEX）。

**服务端设置**：监听地址与端口、最大连接数（0 = 不限）。

**服务端功能**：实时客户端列表（地址、接入时间），可对全部客户端广播或指定单播，支持踢出指定客户端；每条报文标注来源对端。

### 2. WebSocket 客户端 / 服务端

**客户端**：ws:// 与 wss:// 地址、子协议（Sub-Protocol）、自定义请求 Header（每行 `Key: Value`）、Ping 间隔、TLS 校验开关、文本帧/二进制帧发送模式。可观察握手结果、关闭码与关闭原因，断线后按指数退避自动重连。

**服务端**：监听端口与路径（Path）、子协议、最大连接数、发送模式。支持客户端列表、广播、单播、踢出。

### 3. UDP 客户端 / 服务端

UDP 与前面两种连接最大的区别是它没有「连接」这件事。界面上做了对应处理，避免给出错误的心理暗示：

- **状态只代表套接字就绪**。客户端启动后显示「已连接」，但含义是本地套接字已经绑好、可以收发了，并不表示对端在线；启动日志里会明确写这一点。
- **没有分帧，也没有结束符**。一个数据报天生就是一帧完整报文，边界由协议保证。再套「按分隔符 / 按长度」拆一遍只会把正确的边界切碎，所以这两项在 UDP 会话里直接不出现。
- **没有断线重连**。没有连接自然没有断线，重连退避对 UDP 是空转，界面上不提供。

**客户端**

填「默认目标地址 + 端口」即可发包。本地端口默认 0（系统随机分配），需要对方按固定端口回包时可以指定，比如设备协议要求回到 9412。收到的数据报会在报文行上标出来源 `ip:port`，一眼能看出是不是预期设备在应答。可选开启定时心跳包（内容与间隔自定），用来维持 NAT 映射或做保活探测。

**服务端**

绑定端口收包。对端列表不是「连接列表」，而是按来源地址即时派生的发件人档案：

| | TCP 服务端 | UDP 服务端 |
|---|---|---|
| 对端来源 | `connection` 事件 | 收到数据报时按 `ip:port` 派生 |
| 对端消失 | `close` 事件，精确 | 空闲超时淘汰（默认 60 秒） |
| 「踢出」语义 | 真的断开 socket | 只是不再跟踪，对方仍可继续发包 |

空闲淘汰不是可选项而是必需项：一台机器扫过来的成百上千个临时源端口，不淘汰会把对端列表撑爆。淘汰时间可在新建时调整，填 0 表示永不淘汰。

发送时可以「广播全部」（发给所有已知对端）或指定其中一个。尚未收到任何数据报时无法确定目标，会明确报错而不是静默丢弃。

**广播与组播**

两类会话都支持：

- 勾「允许发送广播」后可发往 `255.255.255.255` 或网段广播地址（如 `192.168.1.255`）。
- 填「组播组地址」（如 `239.0.0.1`）会在绑定后加入该组，TTL 默认 1（只在本网段）。抓组播时通常还需要勾「端口复用」，否则本机已有程序占着该端口就绑不上。

协议解析模板、报文断言告警、录制回放、循环发送、数值曲线、历史落库这些通用能力，UDP 与 TCP/串口完全一致。

### 4. 串口

**设置**：串口号（自动枚举，可刷新）、波特率（含自定义）、数据位、停止位、校验位（none/even/odd/mark/space）、流控（无 / RTS-CTS / XON-XOFF）、DTR 与 RTS 电平。

**功能**：打开/关闭、TEXT/HEX 收发、行结束符追加、断开检测。拔线或驱动异常导致的意外关闭会按指数退避自动重开。

### 5. MQTT 客户端

连 Broker、订阅主题、发布消息。支持 MQTT 3.1.1 与 5.0，`mqtt://` / `mqtts://` / `ws://` / `wss://` 四种传输。

**连接参数**

| 参数 | 说明 |
| --- | --- |
| Broker 地址 | 含协议前缀的完整 URL，端口省略时按协议取默认值 |
| 客户端 ID | 默认随机生成，同一 Broker 上重复会被顶掉 |
| 协议版本 | 3.1.1 或 5.0，5.0 下额外开放 No Local、会话过期等选项 |
| 用户名 / 密码 | 可选 |
| 保活 | 秒，0 表示关闭保活 |
| 清理会话 | 关闭后 Broker 会为该客户端保留离线消息 |
| TLS | 可指定 CA / 客户端证书 / 私钥路径，也可关闭证书校验用于自签环境 |
| 遗嘱消息 | 客户端异常掉线时由 Broker 代为发布，可配主题、载荷、QoS、Retain |

**订阅**

主题过滤器支持 `+`（单层通配）与 `#`（多层通配）。订阅表改动即时生效，只做增量订阅与退订，不会断开连接；改连接参数才需要「应用并重连」。Broker 授予的 QoS 会回显在连接日志里，被拒绝的订阅会明确报出来。

**发布**

发送区多出「发布主题 / QoS / Retain」三个控件。主题、QoS、Retain 属于单次发送动作而非会话配置，所以放在发送区而不是设置面板，配合片段和循环发送可以直接压测。

**报文显示**

每条 MQTT 报文在时间轴上带主题、QoS、Retain 徽标，点击主题即按该主题过滤。载荷按内容自动判断：控制字符占比低的按文本显示，否则按 HEX。

### 6. Modbus 主站（TCP / RTU / RTU over TCP）

以点表为中心的 Modbus 调试台。不用手工拼报文，填好地址与类型就能读出工程值。

**三种传输**

| 方式 | 场景 | 报文形态 |
| --- | --- | --- |
| Modbus TCP | 以太网从站、PLC | MBAP 头 + PDU |
| RTU over TCP | 串口透传网关 | PDU + CRC16，走 TCP |
| Modbus RTU | 直连串口设备 | PDU + CRC16，走串口 |

**点表**

| 列 | 说明 |
| --- | --- |
| 功能码 | 01 线圈 / 02 离散输入 / 03 保持寄存器 / 04 输入寄存器 |
| 地址 | 0 基协议地址。手册给 40001 这类 1 基地址时填「手册值 − 40001」 |
| 类型 | uint16/int16/uint32/int32/float32/float64/bits/string，多字类型自动对齐字长 |
| 系数 / 偏移 | 工程值 = 原始值 × 系数 + 偏移 |
| 单位 | 显示在实时值后面 |
| 轮询 | 毫秒，0 表示不轮询只手动读 |
| 写 | 勾选后该行出现写值输入框，避免误改现场寄存器 |
| 图 | 勾选后该点位进数值曲线 |

实时值一列同时显示工程值与原始寄存器 HEX。32 位量的字序在设备之间分歧极大，工程值明显不对但 HEX 正常时，翻一下字序开关即可。

**字序与字节序**

字序（高字在前 / 低字在前）与字节序（大端 / 小端）两个独立开关组合起来覆盖 ABCD / CDAB / BADC / DCBA 四种排法。

**链路可靠性**

- 请求串行排队，两次请求之间保持最小间隔，避免把从站打爆
- 响应超时可配，失败按次数重试
- TCP 按 MBAP 长度域切帧；RTU 按功能码推算长度加 3.5 字符静默双重判帧
- 事务号不匹配的响应直接丢弃并记日志
- 异常响应（功能码高位置 1）解析出异常码并给出中文说明，时间轴上以红色 `E<码>` 徽标标记
- 地址相邻的点位自动合并成批量读，合并间隔可配

Modbus 会话的时间轴与发送编辑器默认按 HEX 显示（其他协议默认 UTF-8）。

### 7. Modbus 从站模拟（本机扮演 PLC / 仪表）

主站面板只能证明「我发出去的请求长这样」，证明不了「点表配得对不对」。字序、寄存器偏移、工程值系数这三样配错之后依然读得出数字，只是数字是错的 —— 所以需要一个自己完全掌握真值的从站来对账。这个模块就是让本机变成那台设备。

**三种链路，一套数据区**

| 传输方式 | 场景 |
| --- | --- |
| Modbus TCP（监听） | 主站走以太网连过来，按 MBAP 长度域切帧 |
| RTU over TCP（监听） | 主站是串口透传网关的形态，PDU + CRC16 走 TCP |
| Modbus RTU（串口） | 用虚拟串口对模拟真实总线 |

数据区内核与链路无关，同一份配置换传输方式不用重填。

**数据区配置**

| 列 | 说明 |
| --- | --- |
| 名称 | 只用于界面区分，比如「温度组」「阀门线圈」 |
| 数据区 | 保持寄存器 (4x) / 输入寄存器 (3x) / 线圈 (0x) / 离散输入 (1x) |
| 起始 / 数量 | 0 基地址，与主站点表同一套口径 |
| 初值 | 启动时填充；位区自动夹到 0/1 |
| 只读 | 输入寄存器与离散输入按协议天然只读；勾上后保持寄存器与线圈也拒绝写入，用来验证主站的错误处理 |
| 自动变化 | 不变化 / 递增斜坡 / 正弦波 / 随机 / 翻转（位区），可配周期、上下限与步进 |

**只有声明过的地址才存在。** 主站读一个没声明的地址会收到异常码 `0x02 非法数据地址`，而不是悄悄返回 0。这是本模块最关键的一条设计：如果越界也给 0，那么「点表里地址填错一位」这个经典 bug 会被完美掩盖，界面上照样有读数。

**实时值页**

每个数据区按每行 10 格的网格铺开（几十上百个地址纵向排要滚很久）。位区点一下直接翻转，寄存器区点开就地改值。主站写进来的值实时反映在这里，可以直接确认「主站写 42 到 p1」是否真的落进了 5 号保持寄存器。单区地址超过 200 个只渲染前 200 格，避免一屏画上万个节点。

**故障注入**

| 项 | 用途 |
| --- | --- |
| 应答延迟 | 验证主站的超时与重试分支是否真的生效 |
| 丢包率 | 制造随机无应答，看主站会不会卡死或误判离线 |
| 强制异常码 | 固定返回 0x01 / 0x02 / 0x03 / 0x04 / 0x06，检查主站的异常提示与恢复 |

延迟与丢包做在适配器层而不是数据区内核里，因为它们属于链路特性；内核保持纯函数形态，请求进、响应出，可以单独验证。

**若干细节**

- 从站地址（Unit ID）不匹配时**静默丢弃**，不回异常码 —— 真实总线上多台从站共享一条线，乱应答会污染别人的回包。也可以勾「接受任意从站地址」，让一个会话冒充整条总线
- 监听失败不做退避重连：端口被占用就是配置问题，反复重试只会掩盖它。502 属于特权端口，本机自测建议用 5020
- 改数据区即时生效，不会断开已连接的主站；改链路参数才需要重启监听
- 发送框留作手动置值的快捷入口，格式 `holding 5 1234`，避免出现一个「点了没反应」的发送按钮

### 8. HTTP Mock 服务（模拟后端接口）

在本地启动一个真实 HTTP(S) 服务，按路由规则返回可配置响应，供前端/移动端在真实后端未就绪时联调。

**路由匹配**
- 方法：GET / POST / PUT / DELETE / PATCH / OPTIONS / HEAD / ANY
- 路径：精确 `/api/health`、路径占位 `/api/users/:id`、通配 `/files/*`、正则 `re:^/v[0-9]+/ping$`
- 进一步筛选：按 Query（如 `status=ok`）、按 Header（如 `x-token: abc`）
- 多规则按优先级排序，取首个命中

**动态响应（模板模式）**
在响应体中插入占位符即可回显请求数据或生成动态值：

```
{{path.id}}      路径参数
{{query.page}}   查询参数
{{body.userId}}  请求体 JSON 字段（支持嵌套 a.b.c）
{{header.token}} 请求头
{{now}}          ISO 时间
{{ts}}           毫秒时间戳
{{uuid}}         随机 UUID
{{sequence}}     自增序号
{{randomInt}}    随机整数
```

**动态响应（脚本模式）**
在 vm 沙箱中运行 JS，可做条件分支、鉴权校验、有状态读写：

```js
// 可用变量：req / res / state
// req: method, path, params, query, headers, body, json
if (!req.headers.authorization) {
  res.status = 401
  res.body = { error: 'unauthorized' }
} else {
  state.hits = (state.hits || 0) + 1
  res.status = 200
  res.body = { id: req.params.id, hits: state.hits }
}
```

**其他能力**
- 有状态 Mock：`state` 为服务级内存数据集，可构造「可读写的假后端」
- 故障注入：按概率返回指定错误码、附加响应延迟，用于客户端健壮性测试
- 单路由延迟：模拟慢接口
- 未命中处理：返回 404，或**代理透传**到真实后端（实现「部分接口 Mock、其余走真实」）
- 自动 CORS：含 OPTIONS 预检处理，浏览器可直接调用
- 请求日志：实时列出方法、状态码、耗时、命中路由，点开可看请求/响应完整报文，支持过滤与清空；列表同样使用虚拟滚动，海量请求下不卡

**录制转路由（把真实流量固化成 Mock）**

手写路由是 Mock 里最枯燥的活：真实后端明明在跑，却要人肉把每个接口的路径、状态码、响应体抄一遍。开代理透传让前端照常跑一遍，再点工具栏「录制转路由」，勾一下就能批量生成。

1. 路由配置 → 未命中处理 → 选「代理透传」并填上游地址（如 `http://127.0.0.1:8080`）
2. 启动 Mock，让前端 / 接口工具把请求打到 Mock 端口，工具栏会显示「代理透传」徽标与录到的请求数
3. 点「录制转路由 (N)」，确认草稿列表后点「生成 N 条路由」

面板里的信息与开关：

- **路径参数自动命名**：`/api/users/1001/orders/77` → `/api/users/:userId/orders/:orderId`（数字段、UUID、≥16 位 hex 都会转参数，参数名取前一段的单数 + Id）
- **同接口自动合并**：同方法同模式只生成一条，`×2` 表示由 2 个请求合并而来，示例响应取最后一次成功响应
- **响应不一致**：同一模式录到了不同响应体（分页接口很常见）。静态路由只能回放其中一份，看到这个标记可以考虑改用脚本模式
- **优先级自动排**：固定路径天然压过带参数的路径，不必手调数字
- **只转未命中路由的请求**：默认开，已有路由在管的接口不再重复生成
- **忽略 4xx / 5xx**：默认开，错误响应通常不是想固化的契约
- **已有同路径**：选「跳过」保留现有配置，选「覆盖」用真实响应刷新（路由名保留）
- **同时存为场景**：额外生成一个带时间戳的快照场景（如「真实快照 08-29 16:20」）并立即激活，之后随时能在「真实后端快照」和「异常注入」之间切

注意：未开代理透传时能录到的只有 404，面板顶部会给出提示与「去设置」入口。

**场景库（一套路由挂多套响应）**
同一批路由可以挂多个「场景」，顶部下拉一键切换，无需反复改路由配置。切换后立即生效，日志行会标出当次请求命中的场景名。

- 内置四个开箱即用场景：登录过期 401、服务不可用 500、慢接口 3s、接口未上线 404
- 场景采用**字段级覆盖**：勾选要改的字段（启用状态 / 状态码 / 延迟 / 响应体），其余仍走路由原始配置，改状态码不必复制整段响应体
- 场景可临时禁用某条路由，让请求走「未命中」分支，模拟接口尚未上线
- 场景可自带故障注入参数，覆盖全局设置，用于整站故障演练
- 支持新建、重命名、删除场景与备注说明；命令面板（Ctrl+K）里也能直接切换场景

**HTTPS 与证书（工具栏「证书」）**

前端要测 `https://` 才复现得出来的问题（Secure Cookie、混合内容拦截、Service Worker）时，Mock 需要一张服务器证书。新建会话勾了「启用 HTTPS」会**自动生成一张自签证书**，直接就能启动，不必先去别处准备。

- **生成自签证书**：填主机名与 IP（逗号分隔，会写进 SAN），有效期默认 825 天 —— 这是 Chrome / Safari 接受的上限档位，填更长反而会被判无效
- **体检卡**：主题、签发者、有效期与剩余天数、适用域名、私钥是否匹配、指纹、文件落盘位置一屏看完；剩余不足 14 天启动时会在日志里给出提醒
- **导入已有证书**：分两步选证书文件与私钥文件（刻意不做多选，避免两个 `.pem` 被认错导致握手失败这种难查的问题）
- **粘贴 PEM 正文**：适合从密钥管理系统复制出来的场景，校验不通过不允许应用，避免存下一个必定起不来的配置
- **浏览器仍提示不安全**：自签证书已带 CA 标记，点「导出证书…」后导入系统信任库即可消除

证书与私钥存放在用户数据目录的 `certs/`（不是安装目录，卸载重装不会被覆盖），私钥文件权限为 `0600`。若启用了 HTTPS 但证书为空，工具栏按钮会变成红色的「证书缺失」，启动时也会直接给出中文原因而不是抛一段底层报错。

### 9. HTTP 接口测试（API Client）

请求由主进程发出，**不受浏览器 CORS 限制**，可直接调任意接口。

- **请求构造**：方法选择、URL 地址栏、Query 参数表（可逐条启用/禁用）、Header 编辑（常用头补全）、Body（none / JSON / text / XML / form-urlencoded / binary，JSON 一键格式化）
- **认证**：无 / Basic / Bearer Token / API Key（可放 Header 或 Query）
- **响应查看**：状态码与状态文本、耗时、响应大小、重定向次数；响应体美化/原始切换、响应头列表
- **网络细节**：自动解压 gzip / deflate / br、跟随重定向（303 转 GET）、超时控制、TLS 校验开关
- **环境与变量**：多环境管理，`{{baseUrl}}`、`{{token}}` 等占位符在 URL / Header / Body / Auth 中统一替换
- **集合与历史**：请求可命名保存到集合；历史自动记录并可一键重放（本地持久化）
- **断言测试**：状态码、耗时阈值、JSON 字段（如 `data.list[0].id`）、文本包含、正则匹配，结果以通过/失败标记
- **变量提取**：从响应体 JSON 路径、响应头或状态码取值，存为变量（发送后自动写回当前环境），后续请求用 `{{变量名}}` 直接引用
- **cURL**：粘贴 cURL 命令导入，或把当前请求导出为 cURL

#### 集合批量运行（Runner）

接口测试面板右上角「批量运行」，把集合里保存的请求按顺序跑一遍，适合冒烟回归。

- **执行控制**：勾选参与的请求、↑↓ 调整顺序、设置请求间隔（毫秒）、开启「失败即停止」
- **变量串联**：以当前环境变量为基线，每步的提取结果并入运行时变量池，供后续请求引用。典型用法是第一步登录提取 `token`，后续请求在 Auth 里填 `{{token}}`
- **结果面板**：用例通过数 / 断言通过数 / 跳过数 / 总耗时四项统计，下方逐条列出状态码、耗时、大小、断言明细与提取值
- **报告导出**：导出 Markdown（统计 + 明细表格 + 逐条断言）或 JSON（原始结构，便于接入 CI），弹出系统保存对话框选择位置

#### 接口定时巡检

接口测试面板右上角「定时巡检」，或左栏图标条 / 「工具」菜单 / `Ctrl+K` 里的「接口巡检」。把已保存的集合按周期自动跑一遍，断言失败就弹系统通知——挂机盯接口时不用一直手点发送。

**关掉面板仍在后台运行**，这是它和「批量运行」的根本区别。面板只是配置入口。

- **周期**：10 秒 / 30 秒 / 1 / 5 / 15 / 30 分钟 / 1 / 6 小时
- **环境**：跟随当前环境，或锁定某个环境（巡检生产和巡检测试往往要用不同 baseUrl）
- **巡检范围**：不勾选任何请求 = 集合全部，之后往集合里新增的接口自动纳入；也可只勾几个
- **通知**：仅失败时通知 / 每次都通知 / 不通知。失败通知可设「连续失败 N 次才通知」，压掉网络抖动造成的偶发告警
- **巡检历史**：每次运行留档时间、通过数、断言数、总耗时；失败时行内直接显示「哪个接口 → 哪条断言没过」
- **红点提示**：有失败时左栏「接口巡检」图标与「工具」菜单项出现红点，打开面板即视为已读
- 任务与历史本地持久化，重启应用后继续按周期运行；历史保留最近 200 条

巡检与手动批量运行共用同一套执行引擎，因此「手动跑通过、巡检报失败」这种判定漂移不会发生。

#### 报文断言告警与告警中心

会话工具栏「告警」按钮，或左栏图标条 / 「工具」菜单 / `Ctrl+K` 里的「告警中心」。

接口测试有断言，收发报文原本没有——设备半夜温度飙到 90 ℃、状态字翻成非零，只能靠人盯着时间轴。这个功能把断言补给了报文侧。

**规则怎么配**

- **判定对象**三种：
  - *解析字段*：用协议解析模板把报文拆成字段，对某个字段的数值判定。支持大于 / 小于 / 等于 / 不等于 / 落在区间 / 超出区间，字段带单位时提示里会带上（`温度 82.4 ℃ > 80 ℃`）
  - *报文文本*：按 UTF-8 解码后做包含 / 不包含 / 正则 / 等于 / 不等于
  - *校验结果*：模板配了 sum8 / xor8 / CRC16 时，校验不符即命中
- **作用范围**：全部支持告警的会话 / 按连接类型（换台设备重建会话不用重配）/ 指定某个会话（临时排查）
- **方向**：接收 / 发送 / 不限
- **级别**：警告（黄）/ 错误（红）
- **冷却**：不冷却 / 10 秒 / 30 秒 / 1 分钟 / 5 分钟。高频链路上一条异常往往连着来几百条，冷却期内同一规则只记一次
- **命中动作**：高亮报文行、系统通知、自动断开会话（出问题就停下来保留现场）

**告警中心**

- *告警记录*页把报文告警与巡检失败按时间倒排在一条时间线上：时间、来源（会话 + 方向 / 巡检任务）、触发说明、报文快照 HEX，一键导出 CSV
- *报文规则*页管理规则，列表里直接显示每条规则的累计命中次数——配完范围后最常见的疑问是「它到底管不管这个连接」，数字摆在眼前比回去核对更快
- 有未读时左栏「告警中心」图标与「工具」菜单项出现红点，打开即视为已读

**实现上的两个注意点**

- 判定挂在收帧路径上，规则表为空时第一行即返回，不解码不解析——没配告警的用户不承担任何成本
- 改完规则会清掉该规则的冷却。否则把阈值从 80 调到 20，报文明显超标却不报警，实际是上次命中的冷却没过，这最容易被当成 bug

### 10. 数据收发与显示（通用）

- **三种视图**：TEXT / HEX / Base64 随时切换，同一条报文可换视角查看
- **报文信息**：序号、毫秒级时间戳、方向（TX/RX）、字节数、来源对端
- **过滤与控制**：关键字过滤、自动滚动开关、清屏；顶栏实时显示报文条数（过滤时显示「命中/总数」）
- **虚拟滚动**：时间轴只渲染可视区域的行，内存缓冲上限 5 万条。两万条报文实测只有约 20-30 个行节点，滚动帧耗时与空闲时基本一致
- **导出报文**：一键导出为 CSV（含 TEXT 与 HEX 两列，带 UTF-8 BOM，Excel 直接打开不乱码）或 TXT（保留时间轴格式）。导出的是当前过滤后的结果
- **发送**：TEXT/HEX/Base64 输入，可追加结束符（无 / CR / LF / CRLF），Ctrl+Enter 快捷发送
- **循环发送**：按毫秒间隔重复发送当前内容，用于压力与心跳测试
- **发送片段**：常用报文存为片段，一键发送（本地持久化）
- **发送区可调高**：发送区上沿有一条拖拽把手，向上拖变高、双击复位。高度会被记住（跨会话、跨重启），不必每次进来重新拉

### 11. 断线重连与连接日志

TCP 客户端、WebSocket 客户端、串口都支持自动重连，等待时长按 2 倍指数递增并封顶，避免对端长期不在时疯狂刷屏。

| 参数 | 说明 | 默认 |
|------|------|------|
| 首次等待 | 第一次重连前的等待时长 | 1000ms |
| 等待上限 | 单次等待的封顶值 | 30000ms |
| 次数上限 | 达到后停止重连并置为错误状态，0 = 不限 | 0 |

实际序列形如 1s → 2s → 4s → 8s → 16s → 30s → 30s…，并叠加最多 20% 的随机抖动，避免多个会话在同一时刻集体重连。连接成功后退避立刻归零，下次断线重新从首次等待开始。手动停止不会触发重连。

**连接日志**：连接建立、断开、重连预告、放弃重连都会作为带「连接」标记的独立记录写入时间轴，并按级别着色（建立为绿、断开与重连预告为黄、放弃为红）。工具栏的「仅连接日志」开关可只看这一类，快速回溯「什么时候断的、重试了几次」。重连成功时会注明「重连第 N 次后成功」。

### 12. 协议解析模板（把裸字节渲染成字段表）

TCP / 串口收到的是一串十六进制，靠人眼数字节容易出错。定义一次帧结构，报文时间轴就能直接展开成字段表。

**支持的字段类型**

| 类型 | 说明 |
|------|------|
| uint8/16/32、int8/16/32 | 整型，多字节可选大端/小端 |
| float32、float64 | IEEE 754 浮点 |
| HEX 串 | 按字节数取原始十六进制；长度填 0 表示吃掉剩余字节 |
| ASCII | 按字节数解码为文本 |
| BCD | 每字节两位十进制，常见于仪表时间/编号字段 |
| 位图 | 展开为 8 位二进制，方便核对标志位 |

**工程值换算与枚举**
- 倍率 + 偏移：显示值 = 原始值 × 倍率 + 偏移。例如温度寄存器 `00 FA` 配倍率 0.1，直接显示 `25 ℃`
- 单位：显示在数值后
- 枚举映射：填 `1=读取,2=写入,3=心跳`，命令码 `01` 直接显示「读取」
- 备注：给字段加说明，鼠标悬停可见

**尾部校验**
可选和校验（1 字节）、异或校验（1 字节）、CRC16-Modbus（2 字节，低字节在前）。校验范围为首字节到校验位之前，结果以「校验通过 / 校验不符」标签显示，不符时展开按钮标红并带 ⚠。

**适用模块（1.8.3 起）**
模板顶部可勾选「适用模块」：只勾 Modbus 的模板，就只出现在 Modbus 会话的解析下拉里。不勾任何模块 = 通用模板，所有会话都能选。模板列表左上角可在「本模块 / 全部模板」之间切换，新建模板默认归属当前会话的协议。

这条改动解决的问题很具体：内置的 Modbus 示例里有「从站地址」「起始地址」两个字段，它们只在 Modbus 链路上成立，可之前串口、WebSocket 会话的解析下拉里也躺着这个模板，选中后字段名和真实报文完全对不上。

**模板匹配**
- 匹配前缀：只解析以指定 HEX 开头的报文（如 `AA55`）；留空表示不限
- 方向过滤：收发都解析 / 仅发送 / 仅接收
- 「自动匹配」模式下按前缀长度择优，前缀更具体的模板优先命中

**半包友好**
字节不足时不整体报错，而是照常显示已解析出的字段，并把断掉的那一项标为「字节不足」。调试现场经常遇到半包，能看到「前几个字段是对的」比一句解析失败有用得多。

**使用方式**
1. 报文区工具栏点「模板」打开编辑器，定义字段并用样例 HEX 即时预览
2. 工具栏「解析」下拉选择模板，或选「自动匹配」
3. 每条报文右侧出现模板名按钮，点击展开/收起字段表；勾掉「全部展开」可改为按需点开
4. 命令面板（Ctrl+K）也能直接切换解析模板

内置两个示例模板：一个「AA55 帧头 + 命令码 + 长度 + 温度 + 状态位 + 载荷 + 和校验」的自定义协议，一条 Modbus RTU 读保持寄存器。模板保存在本地，跨会话复用。

### 13. 数值曲线（报文里的数字画成折线）

协议解析已经把字节变成带工程值的字段，顺势就能把某个数值随时间画出来。调温度、看传感器漂移、观察控制量震荡，看曲线比翻日志直观得多。

**用法**
1. 打开「模板」，给数值字段勾上「曲线」（内置示例的温度字段默认已勾）
2. 报文区工具栏出现「曲线」按钮，点开即在时间轴下方展开折线图
3. 图例显示当前值、最小、最大、均值与采样点数；点图例可临时隐藏某条曲线
4. 「导出 CSV」把所有序列按时间戳对齐导出，可直接丢进表格继续分析

**说明**
- 支持多字段同图：勾了几个字段就画几条线，各自配色并列在图例里
- 只取最近 1000 个采样点。曲线是看趋势的，几万条历史全画既没意义也拖慢渲染
- 只在面板打开时才计算，收起后不占用高吞吐下的渲染预算
- 纵轴自动定界并留 8% 余量；若数值恒定不变，则给一个对称余量避免折线贴边
- 半包或校验不足的报文不产生数据点，不会在曲线上留下假的尖峰

### 14. 报文录制与回放

排查偶发问题时，现场抓到一次异常往往就没了。把那段收发存成文件，之后一键按原时序重放，可以反复复现给同事看，也能拿来给协议解析模板做回归。

**录制**
报文区工具栏点「录制」，把当前时间轴上的报文（含过滤结果）存成 `.json` 文件。文件里存的是**相对时间**而非绝对时间戳，所以任何时候打开都能复现原始节奏，也方便手工编辑时序。

**回放**
点「回放」选择录制文件，时间轴下方展开控制条：

- 播放 / 暂停 / 继续 / 停止 / 重播
- 倍速 0.25× / 0.5× / 1× / 2× / 5× / 10×，播放中可随时切换
- 进度条与「已播帧数 / 总帧数 · 已用时间」实时显示
- 头部显示录制概况：帧数、收发分布、总时长、字节量、录制备注

**说明**
- 回放帧在时间轴上带「回放」角标，与真实链路数据一目了然地区分
- 回放只往界面注入数据，**不会真的往链路上发送**，所以拿生产环境的录制来分析是安全的
- 回放帧同样走协议解析，可以配合字段表和数值曲线一起看
- 时序采用「追赶应到时刻」而非固定间隔累加：定时器本身有抖动，累加会让长录制越走越偏，对齐起点则误差不累积
- 载入非本工具的文件或格式损坏时会给出明确原因，不会静默失败
- 录制文件里 `offsetMs` 乱序也能正常回放，载入时会自动按时间重排

### 15. 报文标注与书签

排查时经常是这样：报文刷了几千条，终于看到可疑的那一条，可等你去翻文档、问同事、跑另一个用例回来，时间轴已经滚过去了。书签就是为这一刻做的——把那条报文钉住，写一句话说明它为什么可疑，之后随时回来看。

**打书签**

- 每条报文行首都有一颗星，平时半透明，鼠标移到行上才显现，点一下变金色 ★ 即为已标注
- **右键星标**：直接打上书签并弹出书签面板，光标落在标注输入框里，适合「边看边写」
- 报文区工具栏的「标注 (N)」按钮显示当前会话的书签数，点击打开面板；`Ctrl + M` 是全局快捷键，顶部「工具」菜单和命令面板里也有入口
- 系统事件行（连接、断开、错误）同样可以标注，用来标记一次断线的确切时刻

**书签面板**

- 顶部会话下拉只列出真正有书签的会话，避免一长串空会话
- 关键字搜索同时匹配标注文字、HEX 与文本内容
- 每条书签显示方向、时间、字节数、来源会话名与类型，下面是 HEX 与文本快照，再下面是可拉伸的标注输入框（失焦即保存）
- 「跳回会话」会自动切到那个会话的标签页并滚动定位到该行
- 「导出 Markdown」把筛选结果导成一份可直接贴进工单或聊天的排查记录

**几个设计取舍**

- **书签存的是自洽快照，不只是报文 ID**。报文缓冲是内存态，清屏或重启后只留 ID 的书签会变成一排点不开的空行。所以打书签时就把方向、时间、字节数、HEX 与文本一起存下来，脱离原会话也能看懂；原会话被删了也只是「跳回会话」变灰，内容仍在。
- **上限 500 条、单条 HEX 快照截断 128 字节**。书签是人工挑出来的线索，不是第二套历史库（历史库见第 27 节，那才是全量落盘的地方）；给它无限容量只会让 localStorage 撑爆、启动变慢。
- **未标注的星用透明度显隐，而不是鼠标移上去才插进 DOM**。后者会让整行在 hover 瞬间横向抖一下，报文快速刷动时非常晃眼。
- **定位优先级：书签定位 > 分屏联动**。两者都想控制滚动位置时，用户刚点的「跳回会话」显然更该赢。
- **导出选 Markdown 而不是 CSV**。书签的产物是给人读的排查记录，不是给表格软件算的数据。
- 如果目标报文已被清屏或超出缓冲，会在顶部给一条明确提示，并告诉你可以用 `Ctrl + H` 去历史库里检索，而不是静默什么都不发生。
### 16. HAR 导出（把请求发给同事复现）

排查接口问题最常见的卡点不是技术，是沟通：「我这边参数是这么传的」——然后开始截图、复述、来回确认。HAR 是 Chrome 开发者工具、Postman、Fiddler、Charles 都能直接打开的标准格式，导出一份发过去，对方拖进浏览器就看到完整的请求头、载荷、响应体和耗时。

**三个导出入口**

| 入口 | 导出内容 | 头部是否完整 |
|------|----------|--------------|
| 接口测试面板 · 历史区「导出 HAR」 | 最近 100 条请求，含响应体（单条截断到 8 KB） | ✅ 完整，且认证头已还原 |
| Mock 会话工具栏「导出 HAR」 | 当前过滤结果对应的请求日志 | ✅ 完整 |
| 报文历史 · HTTP 请求页「导出 HAR」 | 库里查询条件命中的请求（上限 5 万条） | ⚠️ headers 为空 |

**几个要点**

- **认证头会被还原**。接口测试里 Bearer / Basic / API Key 是单独配置的，不在 Header 表里。导出时按真实发送逻辑补齐 `Authorization`，对方拿到才能直接重放，不会一片 401。代价是 token 会明文落进文件里，转发前请自行斟酌。
- **变量已展开**。`{{baseUrl}}/v1/login` 这类写法在 HAR 里是展开后的真实地址 —— 对方没有你的环境变量表。
- **Mock 侧按当前过滤结果导出**。过滤条件是你刚刚表达的意图，导出时忽略它、把全部日志塞进去，等于让人回去手工删。按钮上会显示将导出的条数。
- **历史库导出的 HAR 没有头部**。历史库的表结构里只有方法、路径、状态码、耗时与正文，没存请求头与响应头 —— 那部分按十万行量级存起来体积可观，而多数时候不会被读。DevTools 依然能打开，只是 Headers 一栏为空，每条记录的备注里也写明了这一点。需要完整头部就用 Mock 会话那个入口。
- **时间戳带时区**。写的是 `2026-08-31T14:00:00.000+08:00` 而不是 UTC，和现场日志对时间时不会差 8 小时。
- 耗时未知的记录写 `-1`（HAR 规范里表示未知）而不是 `0`：写 0 会在 DevTools 里画成零宽时间条，看起来像请求瞬间完成。
- 每条记录的备注里带上来源、命中路由与 Mock 场景名。同一个路由在不同场景下返回完全不同，缺了场景名这份文件会让人对不上。
### 17. 分帧（解决 TCP/串口粘包半包）

四种策略可选：

| 模式 | 说明 |
|------|------|
| 不分帧 | 收到即上报 |
| 分隔符 | 按指定分隔符切分（HEX 表示，如 `0d0a`） |
| 长度域 | 按帧头中的长度字段切分，可配偏移、字节数、修正值、字节序 |
| 静默超时 | 一段时间无新数据即视为一帧结束 |

### 18. 工具箱

- **校验和**：CRC8 / CRC16 / CRC32 / LRC / Checksum 等，支持 TEXT/HEX 输入
- **进制转换**：二 / 八 / 十 / 十六进制互转
- **时间戳**：时间戳与日期时间互转

### 19. 系统功能菜单栏（系统功能 vs 模块功能）

界面上的功能被明确分成两类，位置不再混在一起：

| 类别 | 判定标准 | 位置 | 例子 |
|------|----------|------|------|
| **系统功能** | 与「应用本体」有关，跟当前打开哪个会话无关 | **顶部菜单栏** | 窗口控制、视图布局、主题、密度、缩放、数据目录、配置导入导出、诊断、关于 |
| **模块功能** | 与「某个协议 / 某个会话」有关，操作对象就在眼前 | 左栏 / 中栏 / 右栏原位 | 连接参数、收发编辑器、Mock 路由、断言、协议模板、分组标签 |

顶部是自绘标题栏 + 菜单栏（无原生窗口边框），五组菜单：

- **文件**：新建连接、复制当前会话、导入 / 导出配置、打开工作区目录、打开历史库目录、退出
- **会话**：启动 / 断开 / 重新连接、重命名、清空报文时间轴、删除会话（禁用态会随当前会话状态自动灰掉）
- **视图**：左侧栏 / 检查器开关（✓ 勾选态）、数据看板、报文历史、全局搜索、命令面板、三档主题、三档密度（• 单选圆点）、放大 / 缩小 / 恢复缩放
- **工具**：HTTP 接口测试、编解码工具箱、全局搜索历史、报文历史浏览器
- **帮助**：使用文档（`F1`）、快捷键一览、关于、检查更新、重启应用（开发者工具只在源码运行时出现，安装版已屏蔽）

菜单模型是纯数据（`components/menu/menuModel.ts`），同一份定义同时喂给菜单栏与命令面板，不会出现「菜单里有、Ctrl+K 里没有」的分裂。

右上角是自绘的最小化 / 最大化 / 关闭三键，关闭键 hover 变红（`#c42b1c`），标题栏其余区域可拖拽窗口，双击最大化。

> **关于窗口最大化**：早期版本窗口用了 `transparent: true`，Windows 下会走分层窗口路径，Electron 连带把 `maximizable` 关掉，最大化按钮点了没反应。现在改为 `titleBarStyle: 'hidden'` + `backgroundMaterial: 'acrylic'` + `backgroundColor: '#00000000'`，视觉效果一致但最大化 / 双击标题栏 / 拖到顶部贴边全部正常。

### 20. 界面密度与缩放

同一套界面在 13 寸笔记本和 27 寸显示器上的合适信息量差别很大，因此提供两个独立维度：

- **密度**（视图 → 密度）：紧凑 / 标准 / 宽松三档，改的是控件高度与内边距令牌（`--control-h` 紧凑 26px、标准 30px、宽松 34px），字号不变，所以文字不会变小、只是行更密
- **缩放**（`Ctrl+=` / `Ctrl+-` / `Ctrl+0`）：整体等比缩放，范围 0.7×–1.6×，走 Electron `webFrame.setZoomFactor`，字号与控件一起放大

两者都会持久化，下次启动保持上次选择。

### 21. 中栏标签页

中栏顶部是一排浏览器式标签，可以同时挂着几个会话来回切，不必每次回左栏长列表里翻——尤其是左栏还开着筛选条件的时候。

**预览标签与常驻标签**

左栏随手点开的会话是「预览标签」，标签名显示为斜体，它们共用同一个位置反复替换，所以浏览会话不会攒出一长排标签。想留下某个会话，有四种方式：

- `Ctrl+单击` 左栏的会话
- 双击左栏的会话
- 双击标签本身
- 在这个会话里发一次报文（发过就说明在用它，自动转为常驻）

**标签操作**

| 操作 | 方式 |
|------|------|
| 切换 | 单击标签，或 `Ctrl+Tab` / `Ctrl+Shift+Tab` 循环 |
| 关闭 | 标签上的 `×`、中键单击、`Ctrl+W` |
| 批量关闭 | 右键标签 →「关闭其他标签」「关闭右侧标签」「全部关闭」 |
| 排序 | 直接拖动标签 |
| 新建 | 标签条右端的 `+` |

标签多到装不下时，把鼠标放在标签条上滚滚轮即可横向滚动；`Ctrl+Tab` 切到屏幕外的标签会自动滚动到可见位置。标签顺序与常驻状态都会保存，重启应用后原样恢复；会话被删除时对应标签自动消失。

`Ctrl+Tab` 只在已打开的标签之间循环（这点和浏览器一致），没有标签时才在全部会话之间循环——工作区里存着几十个会话时，逐个 Tab 过去没有意义。

### 22. 分屏并排与报文对比

排查「A 设备正常、B 设备不正常」这类问题时，来回切标签很容易记错刚才看到的是哪一边。分屏让两个会话的报文时间轴并排显示，报文对比则直接告出哪一个字节变了。

**进入分屏（三种方式，选顺手的）**

- 把标签拖到中栏右半边，出现「松开放到右半区并排对比」提示后松手
- 右键标签 →「在右侧打开」
- 视图菜单 →「在右侧并排打开」，或按 `Ctrl+\`

分屏后中间有一条可拖动的分隔条调整左右宽度（双击回到对半），标签上会带一个 `⇥` 标记表示它正在右半区。右键标签可「左右互换」或「退出分屏」。

分屏时两侧会自动收窄：右侧检查器与协议模板、录制回放、导出这类低频按钮先让位给报文区。这不是功能减少，退出分屏立刻恢复——半宽栏里硬排十来个按钮会把工具条堆成三四行，报文反而看不见了。

**时间轴联动**

分屏后工具栏出现「时间轴联动」勾选框。勾上以后滚动任意一侧，另一侧会按时间戳跟到同一时刻，用来对比上下游报文的时序（比如客户端什么时候发的、服务端什么时候收的）。两侧报文的疏密不同也没关系，对齐按时间而不是按行数。

**报文对比（字节级 diff）**

1. 点工具栏的「对比」进入挑选模式，报文行首会出现一个选择位
2. 勾两条报文——同一个会话里的两条，或者分屏后左右各挑一条都行
3. 勾满两条自动弹出对比面板，按钮上会显示 `对比 2/2`

对比面板把两条报文上下并排成 HEX 视图，一行 16 字节，偏移列在最左。差异位用加深底色加粗显示，只在其中一侧存在的字节额外加下划线。头部给出「相同 / 不同 / 仅左 / 仅右」四个计数，完全一致时直接告诉你一致。

面板左上角可切到「字段表」视角：两条报文各自按协议解析模板解析后逐字段并列，差异行整行高亮。这一视角依赖协议模板，没配模板时会提示去哪里配。

对齐用的是序列比对（LCS）而不是逐位置比较。差别在于：如果报文中间插入了一个字节，逐位置比会把插入点之后的所有字节都标成「不同」，满屏红噪声；序列比对能识别出「这里插入了一个字节，后面其实没变」。报文特别长（超过 150 万比对格）时会自动退化为逐位置比较并在头部挂出「逐位置比较」提示，这是为了不让渲染卡死。

已经挑满两条后继续勾第三条，会替换掉较早那条——方便「固定一个基准，依次和后面几条比」。点「重选」清空，再点「对比」按钮退出挑选模式。

### 23. 界面与体验

- **三档主题**：跟随系统 / 浅色 / 深色，选择持久化；跟随系统时随 OS 明暗实时切换
- **亚克力外观**：窗口用 `backgroundMaterial: acrylic` 做背板透（不再用 `transparent`，否则 Windows 会连带禁用最大化），左栏半透明毛玻璃，中栏与检查器为实底
- **中性配色**：无彩色强调，主按钮为浅底深字（深色主题）或深底白字（浅色主题）
- **两栏可折叠**：左侧栏（Ctrl+B 或标题栏 `⟨`）与右侧检查器均可隐藏，隐藏后中栏铺满
- **单实例限制**：同时只允许运行一个应用实例，重复启动会聚焦已有窗口
- **命令面板**：`Ctrl+K` 打开，模糊搜索会话与命令。可跳转会话（支持按会话名、协议、主机、端口、串口号搜索）、执行操作（新建连接、接口测试、工具箱、数据看板）、控制当前会话（启动或停止、复制会话、切换自动连接、清空报文、删除）、组织会话（移动到分组、移出分组、按标签筛选、清除筛选）、切换界面（左侧栏、检查器、三档主题）。↑↓ 选择、Enter 执行、Esc 关闭
- **配置导入导出**：会话配置与发送片段可导出为 JSON，便于团队共享与版本管理
- **统一下拉框**：所有下拉选择均为自绘组件，圆角、阴影、行高与其余浮层一致；深浅主题下都不出现系统边框；选项超过 8 项自动出现搜索框；支持 ↑↓ / Home / End / Enter / Esc 键盘操作；选中项以右侧勾选标记表示，鼠标与键盘光标以整行高亮表示
- **不被遮挡**：下拉列表挂在页面顶层并按视口定位，在带滚动条的面板或弹窗里展开都不会被裁切；空间不足时自动向上翻转
- **舒适字号**：正文基准 14px（中文字形在高分屏非整数缩放下，13px 以下明显偏糊），标题与辅助文字按同一阶梯上移，控件高度同步跟进
- **多行输入可拖高**：自定义 Header、Mock 响应模板与脚本、接口请求体、工具箱输入的下沿都有一条拖拽把手，按住上下拖即可改高度，双击复位。之所以不用浏览器自带的拉伸手柄：这些输入框都位于弹性布局的容器里，原生手柄写下的高度会在下一次布局被重新压回去 —— 手柄看得见、拖了却没反应，正是之前反馈的问题
- **按钮四级层级**：主操作（创建 / 确定 / 发送，实色高对比）、常驻入口（新建连接、空态按钮，浮起卡片式弱化处理）、次级（面板内动作，淡色叠加无描边）、三级（图标条，透明底 hover 才浮出）。所有按钮与输入框都有悬停与按下反馈

### 24. 会话持久化与工作区

关闭应用后会话不会丢失。新建、改名、改参数、修改 Mock 路由、删除会话时都会立即写入本地工作区文件，下次启动自动重建整个会话列表。

- **保存内容**：会话 id、类型、名称、连接参数（主机/端口/串口参数/分帧/Mock 路由等）、自动连接开关、分组、标签、创建时间
- **不保存内容**：收发报文与运行指标（避免文件无限膨胀，每次启动从干净状态开始）
- **会话 id 保持不变**：恢复后 id 与原来一致，发送片段、集合等按会话 id 关联的数据不会失联
- **自动连接**：在新建对话框或检查器里勾选「下次打开应用时自动连接」，启动后该会话会自动 connect / listen；未勾选的会话恢复为待连接状态
- **恢复顺序**：先重建全部会话，再统一启动需要自动连接的会话，避免端口互相抢占
- **原子写入**：先写临时文件再改名替换，进程被强杀也不会留下半截损坏的配置

工作区文件位置（可在检查器中查看与清空）：

| 平台 | 路径 |
|------|------|
| Windows | `%APPDATA%\flowprobe\workspace.json` |
| macOS | `~/Library/Application Support/flowprobe/workspace.json` |
| Linux | `~/.config/flowprobe/workspace.json` |

**会话管理操作**（右侧检查器顶部「会话」分组）：

- **就地改名**：点「改名」进入编辑，Enter 保存、Esc 取消
- **改参数**：直接修改地址/端口/串口/波特率等主要参数，点「应用并重建」后停掉旧连接并按新参数重建适配器，状态回到待连接
- **复制会话**：一键复制当前会话的全部配置为「XXX 副本」，副本默认不自动连接，避免与原会话抢端口
- **查看存储位置**：显示 workspace.json 的实际路径，便于备份或手工编辑
- **清空存档**：删除所有已保存会话配置，当前窗口不受影响，但下次启动不再恢复

左侧会话列表中，已勾选自动连接的会话会带一个「自动」小标记，一眼看出哪些会随应用启动。

### 25. 会话分组与标签

会话一多，左栏就会变成一条长长的滚动列表。分组解决「按项目收纳」，标签解决「按维度横切」，两者可以叠加使用。

**分组**
- 在右侧检查器的「分组与标签」里输入分组名即可归类，回车或失焦生效；留空表示未分组
- 下方会列出工作区里已有的分组名，点一下直接把当前会话搬过去，不用记之前起过什么名字
- 左栏按分组渲染，分组标题可折叠，标题右侧显示该组会话数
- 具名分组按名称排序，「未分组」始终垫在列表最后
- 命令面板里有「移动到分组：XXX」与「移出分组」命令，键盘党不必碰鼠标
- 复制会话时分组与标签一并带过去，副本天然落在同一组里

**标签**
- 一个会话可以挂任意多个标签，例如同时标「生产」和「网关」
- 输入框支持一次粘进多个标签，逗号、中文逗号、空格都当分隔符，自动去重
- 左栏标签条按使用次数降序列出全部标签，点击即筛选，可再点取消
- 多标签筛选取**交集**语义：勾了「生产」和「网关」，只留同时带这两个标签的会话。标签常用来叠加维度（项目 + 环境），交集才是想要的结果
- 折叠状态与标签筛选写入本地存储，重开应用后保持

**左栏筛选框**
分组标签之上还有一个筛选输入框，同时匹配会话名、分组名、标签、主机、URL、串口号与端口，与标签筛选可以叠加。

分组与标签随会话配置一起落盘到 `workspace.json`，重启后原样恢复。

### 26. 数据看板

单个会话的字段曲线在会话视图里看；看板回答的是全局问题：哪些链路在跑、谁在刷流量、包长分布是否异常、Mock 的错误率与响应耗时如何。

左栏「数据看板」按钮或 `Ctrl+D` 打开，`Ctrl+D` 再按一次或点「返回会话」退出。

**统计范围**
- 作用域下拉：全部会话 / 某个分组 / 单个会话
- 左栏的标签筛选对看板同样生效，看板顶部也有一条标签条可直接切换
- 时间窗口三档：近 1 分钟 / 近 3 分钟 / 近 10 分钟

**六个实时指标**
实时发送、实时接收、报文速率、在线连接数、Mock 错误率、响应 P95。速率取最近 5 个完整时间桶的均值，单桶抖动太大不适合直接展示；错误率超过 10% 会标红。

**六块图表**

| 图表 | 说明 |
|------|------|
| 吞吐趋势 | 发送/接收双序列面积图，桶宽 1 秒，静默期补零不会连成斜线 |
| 会话状态 | 环图统计已连接 / 监听中 / 连接中 / 未启动 / 已关闭 / 错误 |
| 报文长度分布 | 按 8/32/64/128/256/512/1K/1.5K 分档，判断是小包高频还是大包低频 |
| 流量最高的会话 | 收发字节排行，点任意一行直接跳到该会话 |
| 分组流量对比 | 按分组累计收发字节，回答「哪个项目最吵」 |
| Mock 状态码分布 + 热门接口 | 来自 HTTP Mock 请求日志，接口条目标注错误占比 |

**实现取舍**
- 全部图表用原生 SVG 绘制，不引图表库：数据量已在聚合阶段收敛，路径字符串比多引一个依赖划算
- 图表按 1 秒节拍刷新，刷新频率与数据量解耦，几万条报文在场也不会每帧重算
- 桶聚合从最新报文往回扫，遇到窗口外的时间戳立即停止回溯，不做全量遍历
- 响应耗时给 P50 与 P95 而不只是均值：均值会被个别慢请求拉高，P95 才说明「大多数请求有多慢」
- 「导出 CSV」把当前窗口的吞吐序列导出（时间、发送字节、接收字节、发送帧、接收帧）

### 27. 报文历史（SQLite 落库）

内存里的报文时间轴关掉应用就没了，看板也只覆盖最近十分钟。历史模块把每一条报文与每一次 Mock 请求写进本地 SQLite 库，重启之后还能查——排查「昨天下午那台设备发过什么」这类问题必须要有它。

左栏「历史记录」按钮或 `Ctrl+H` 打开，`Ctrl+H` 再按一次或点「返回会话」退出。库文件在 `%APPDATA%/flowprobe/history.db`。

**报文页**
- 筛选：会话下拉（含已删除会话，名称按写入时快照保留）、时间范围五档（近 1 小时 / 24 小时 / 7 天 / 30 天 / 全部）、关键字、方向（全部 / TX / RX / 系统）、仅连接日志、字节数上下限
- 展示格式可切 TEXT / HEX / Base64，点行展开看完整内容与元信息（会话、对端、编码、字节数、时间）
- 每页 200 条，首页 / 上一页 / 下一页 / 末页翻页，列表本身仍是虚拟滚动

**HTTP 请求页**
- 额外筛选：请求方法、状态码族多选（2xx/3xx/4xx/5xx）、最小耗时（找慢请求）
- 行内直接显示方法、状态码、耗时、路径与查询串，展开看请求体与响应体

**存储管理页**
- 落库总开关；「同时保存原始字节」关掉后只存文本摘要，库体积明显更小
- 容量上限：保留天数（0 = 不按时间清理）与报文条数上限（0 = 不限，超出删除最旧），保存后立即执行一次清理
- 库概况：报文数、HTTP 请求数、会话数、文件大小、最早/最新记录时间、近 14 天每日条数柱图
- 按会话占用排行，可单独删除某个会话的历史；也提供压缩数据库（回收删除后的空间）与清空全部

**导出**
顶部「导出 CSV」按当前筛选条件导出，上限 5 万行。查询与 CSV 序列化都在主进程完成，避免把十万行对象经 IPC 搬到界面层再拼字符串。文件带 UTF-8 BOM，Excel 直接打开不乱码。

**实现取舍**
- 用 better-sqlite3 同步 API：写入发生在主进程，批量事务比异步驱动的回调开销更低；Electron 31 内置的 Node 20 还没有 `node:sqlite`
- WAL 模式 + 批写：攒够 200 条或空闲 800ms 落一次盘，用一个事务包住整批。高频报文场景下逐条写会把磁盘打满
- 每次查询前先 flush 队列，否则刚发出的报文查不到，会让人以为丢数据
- 会话名/类型/分组在写入时冗余进行，会话删掉之后历史依然可读
- 按条数清理用「先查阈值 id 再 `DELETE WHERE id < ?`」，走主键索引，比 `ORDER BY ... LIMIT` 子查询快得多
- 回放注入的报文不入库：它不是真实链路数据，混进历史会污染排查结论

### 28. 全局搜索（Ctrl+F）

历史页的筛选要先选会话、再选时间范围、再敲关键字，适合「我知道去哪儿找」。全局搜索解决的是另一半问题：**只记得一个订单号或一个错误码，不知道它出现在哪个会话、哪一天**。

按 `Ctrl+F`（左栏「全局搜索历史」按钮、命令面板同名命令也可）弹出搜索层，输入即搜，报文与 HTTP 请求两张表一次打完。

**结果呈现**
- 命中片段带上下文（前后各 40 字符）并高亮关键字，长内容自动截断
- 结果按时间倒序交织两类来源，行内标出会话名、方向、字节数，HTTP 行额外显示方法与状态码
- 顶部按会话聚合成 chips（如 `订单网关 · 37`），点一下即按该会话收窄
- 状态条给出「命中 N 条 · 显示 M · 扫描 X 行 · Y ms」，慢查询和空结果都一眼可辨
- `↑` `↓` 选中、`Enter` 跳转到历史页并带着关键字继续深挖（历史页行内同样高亮）、`Esc` 关闭
- `Shift+Enter`（或结果行右侧的「前后文」按钮）打开命中行在**原会话时间轴上的前后文**，见下节

**搜索作用域**
两档可选：默认「最近 5 万条」，够覆盖多数排查场景且延迟稳定在个位数毫秒；切「全部历史」做穷尽扫描。会话下拉可再限定范围。

**为什么不用 FTS5**

这是本模块最主要的取舍，我在 30 万行的库上实测过两条路：

| 方案 | 搜索耗时 | 索引开销 | 写入放大 |
|------|---------|---------|---------|
| `LIKE` 全表扫（最坏：无命中） | 68ms | 0 | 无 |
| `LIKE` + 限定最近 5 万条 | 6ms | 0 | 无 |
| FTS5 虚拟表 + 同步触发器 | 0ms | +13MB | 插 2 万行 1558ms vs 83ms，约 **19 倍** |

FTS5 查询确实快到测不出来，但报文库是**写多读少**：每秒可能落几百条报文，搜索一天点几次。为了偶尔一次搜索把常态写入吞吐压到十九分之一，不划算。所以走 `LIKE` + 扫描行数上限：`scanLimit` 用 `id > MAX(id) - N` 走主键索引裁剪，最坏情况也只有几十毫秒。

**两个容易被忽略的细节**
- **文本会话与 HEX 会话能互相命中**：库里存的是按会话显示编码渲染后的文本，同样一条 `ALARM`，TEXT 会话存 `ALARM`、HEX 会话存 `414c41524d`。搜索时会自动补上等价模式——输入文本附加其 UTF-8 十六进制（中文同样适用，`温度` → `e6b8a9e5baa6`），输入十六进制串则附加解码后的可见文本。高亮长度按实际命中的那个模式算，否则 HEX 命中只会亮一半。
- **`%` 和 `_` 按字面量搜**：SQL 通配符与反斜杠都做了转义并显式声明 `ESCAPE`，搜 `%` 得到的是真正含百分号的报文，而不是全库。所有关键字都走参数绑定，不拼 SQL。

**看命中行的前后文**

搜索结果只能告诉你「这条报文长什么样」，但排查往往需要知道「它前后发生了什么」——前一条是不是心跳超时、后一条是不是重连日志。直接跳历史页续查没用，因为历史页的结果全是命中行，中间那些没命中关键字的报文恰恰被过滤掉了。

按 `Shift+Enter` 或点结果行右侧的「前后文」，弹出「历史上下文」浮层：

- 以命中行为锚点，向前后各取 50 条同会话记录，命中行居中显示并带「命中」标签（底色 + 左侧色条 + 加重字色三重标记）
- 顶部显示会话名、协议类型与该会话在历史库中的总条数；`TEXT / HEX / B64` 可切换报文视图；关键字继续高亮
- 上下两端可「↑ 再往前 50 条」「↓ 再往后 50 条」增量加载，到头则明确提示「这是该会话在历史库中最早/最新的记录」
- 「回到命中」把视图拉回锚点；原会话还在的话，「打开实时会话」一键切回它的实时时间轴
- 记录已被保留策略清理时如实提示，不给空白页

### 29. 内置使用文档（`F1`）

需要查手册的时刻，恰恰是手头正卡着的时刻。所以文档做成应用内面板，而不是「去仓库里找个 md 文件看」——跳出应用会打断当前排查，而现场调设备时经常连外网都没有。

**打开方式**：帮助菜单第一项 / `F1` / 命令面板搜「文档」。

**结构**：左目录常驻 + 右正文，共十七章，覆盖快速上手、界面导览、七类协议模块、Mock、接口测试、报文分析、告警、历史检索、工作区、快捷键与常见问题。

| 能力 | 说明 |
|------|------|
| 全文搜索 | 面板内 `Ctrl+F` 聚焦搜索框，目录上直接标出「这一章命中几处」，正文里关键字高亮 |
| 自动跳转 | 搜索后自动切到第一个命中的章节，不用再手动点一遍 |
| 逐章翻页 | 正文底部有上一章 / 下一章，手册是顺序读物 |
| 导出 Markdown | 导出整本，用于存档或发给同事 |

**几个设计取舍**

- **正文是结构化数据，不是 Markdown 字符串**。同一份内容要供两个地方消费：界面面板（需要按章分栏、按关键字计数）与仓库里的 `docs/使用文档.md`（需要标准 Markdown）。若以 Markdown 为源，界面侧得在渲染时解析一遍，而「哪一章命中几处」这类结构信息用正则切段落很快就会失真。反过来由结构化数据生成 Markdown 只是拼字符串，不会出错。
- **`docs/使用文档.md` 由脚本生成，不手工维护**：`npm run docs:guide`。手动同步两份文档，迟早会出现「界面上写的和仓库里的不一样」这种最难发现的偏差。
- **面板内的 `Ctrl+F` 被就地拦下**，不冒泡去开全局报文搜索：文档开着时按 `Ctrl+F`，想搜的显然是文档。
- **搜索无命中的章节压暗而不是隐藏**。整本的目录结构本身就是信息，抽掉一半会让人以为文档变短了。
- **高亮用 DOM 节点拼接而不是 `innerHTML`**：正文里有 `{{}}`、`<>` 这类字符，走 innerHTML 会被当标签解析，还白送一条注入路径。

### 30. 应用自动更新（帮助 → 检查更新）

这是给团队内部用的工具，改一个 Mock 规则、修一个分帧 bug，都不该演变成「群里发安装包 + 挨个提醒重装」。所以更新走应用内自查自装。

**更新地址不可配置，界面里没有任何输入框。** 地址只有一处来源：打包时 `electron-builder.yml` 的 `publish` 段，electron-builder 会把它写进安装包内的 `app-update.yml`，客户端启动时自己读。当前指向公开仓库 `kevinLei736/FlowProbeClient` 的 Release。

早先版本确实让用户在面板里选来源（自建目录 / GitHub 仓库）并填地址与下载代理，理由是「换服务器不用重新打包」。但那等于把一件发布方只需决定一次的事，摊给每一个使用者：他要判断填哪种来源、仓库名怎么写、代理选哪个 —— 而这三处任何一处写错，表现都是同一个 404，用户根本无从判断错在哪。收敛成单一口径后，装好即用。

**打开方式**：帮助菜单最后一组 / 命令面板搜「更新」。

#### 面板能力

| 能力 | 说明 |
|------|------|
| 启动后自动检查一次 | 默认开。启动后延迟 8 秒才查，避开恢复会话、开监听端口、初始化历史库这段 I/O 高峰 |
| 发现新版本后自动下载 | 默认**关**。下完了终究要重启才生效，而重启会掐断正在跑的连接与监听端口，所以下载这一步也交给你决定 |
| 下载进度 | 显示百分比、已传 / 总大小与实时速率 |
| 重启并安装 | 非静默安装，装完自动重新拉起应用 |
| 菜单直接给结论 | 菜单项文案三态：「检查更新…」/「有新版本…」/「有新版本可安装…」，不用点开面板才知道结果 |

#### 分发通道：两个仓库

| 仓库 | 可见性 | 放什么 |
|------|--------|--------|
| `kevinLei736/FlowProbe` | **私有** | 源码、文档、构建脚本 |
| `kevinLei736/FlowProbeClient` | **公开** | 每个版本的安装包与版本清单（Release 附件）|

**为什么必须拆开**：自动更新要能匿名下载附件。私有仓库的 Release 附件每次请求都要带令牌，而把令牌打进客户端就等于公开它 —— 任何人解包 asar 都能拿到，它还带着对源码仓库的读权限。所以「代码私有 + 安装包公开」是唯一站得住的组合；公开的那个仓库里只有二进制，不含一行源码。

```yaml
# electron-builder.yml
publish:
  - provider: github
    owner: kevinLei736
    repo: FlowProbeClient
    releaseType: release   # 只认正式 Release，草稿与预发布不会推给所有人
    publishAutoUpdate: true
```

用 `github` provider 而不是 `generic` 配一个 `releases/latest/download/` 地址，是因为前者直接读 Release 元数据，Release 正文能显示在更新面板里；后者每次取文件都要穿过一层 302 跳转，部分网络下会让 blockmap 增量下载失效。

要换成自建服务器就把这一段改成 `provider: generic` + `url: https://你的服务器/flowprobe/`，服务端只需一个能按路径返回文件的静态服务，把 `release/` 下的 exe、blockmap、`latest.yml` 拷进去即可。客户端两种都认。

发一版的完整流程见 [docs/发布与自动更新.md](docs/发布与自动更新.md)。

#### 几个设计取舍

- **地址由打包决定，而不是运行时可配**。见上文：可配置把发布方的一次性决定变成了每个使用者的必答题，而答错的反馈信号（404）没有区分度。
- **不调用 `setFeedURL`**。地址已经在安装包内的 `app-update.yml` 里，库自己读得到。再设一遍等于让同一个地址有两个来源，两处不一致时排查成本极高。
- **错误按原因分类，而不是笼统报「更新失败」**。「发布仓库里还没有正式版本」「找不到版本清单」「网络连不上」对应完全不同的动作。1.20.0 及更早的包里写的是占位域名 `update.invalid`，客户端认得它并回「发布方尚未启用更新服务」，而不是抛一个域名解析错误 —— 后者是在向用户报告一件与他无关的事。
- **产物名固定为纯 ASCII 且不含空格**（`FlowProbe-Setup-1.21.4.exe`）。默认产物名会带空格，而分发环节（GitHub Releases 上传等）会改写文件名，`latest.yml` 里记的却是原始名字，一旦被改写下载就必然 404。
- **状态用一个扁平的 phase 字段，而不是一堆布尔量**。「正在查 / 有新版 / 正在下 / 下好了 / 已是最新 / 出错了」本质是互斥的六种状态，用布尔量组合迟早出现「既在下载又已是最新」的矛盾组合，界面就得写一堆优先级判断。
- **`electron-updater` 惰性引入，不放在文件顶部**。源码运行时它的构造过程本身就可能抛错，顶层 import 会连累主进程起不来 —— 为了一个可选功能拖垮整个应用不值得。
- **失败原因翻成中文处置建议**，而不是把 `net::ERR_NAME_NOT_RESOLVED`、`sha512 mismatch` 原样丢出来。这里要留意更新请求走的是 Electron 的 `net` 模块，报的是 Chromium 错误码而不是 Node 的 `ENOTFOUND`，两套都得认。地址不可配之后，这些提示一律不再让用户「检查地址」—— 他没有地址可改，能做的只有查网络或者等发布方修好服务器。
- **两个开关单独存 `update.json`，不塞进工作区文件**。工作区是会拷给同事、跟着项目走的；这两个开关属于这台机器上的个人偏好。旧版本存下的 `feedUrl` / `githubRepo` / `githubProxy` 在读取时被直接丢弃，不做迁移 —— 那些字段已经没有对应功能，留着只会让人以为还能生效。
- **更新说明按纯文本渲染**。那段文字来自服务端，不该有能力往界面里插标签。
- **源码运行时明确告知「开发运行不检查更新」**，而不是静默失败。装的是安装版却看到这句，说明跑错了目标。

### 应用图标

图标源文件是 `build/icon.svg`：三条数据流线，中间一条在环形探针处断开——对应 FlowProbe 这个名字。

刻意只用粗直线和一个圆环：这枚图标最小要在 16px 的任务栏与托盘里渲染，曲线、渐变、发光在这个尺寸会糊成一团灰。界面内的 Logo 是独立组件 `src/renderer/src/components/Logo.tsx`，用 `var(--accent)` 取色，深浅主题自动跟随。

如需修改，改完 SVG 后重新生成位图：

```bash
npm install --no-save sharp png-to-ico
node -e "const sharp=require('sharp'),fs=require('fs'),p2i=require('png-to-ico');(async()=>{const svg=fs.readFileSync('build/icon.svg');await sharp(svg).resize(512,512).png().toFile('build/icon.png');const b=[];for(const s of [16,24,32,48,64,128,256])b.push(await sharp(svg).resize(s,s).png().toBuffer());fs.writeFileSync('build/icon.ico',await p2i(b));})()"
```

生成 `build/icon.png`（512×512，窗口图标）与 `build/icon.ico`（16–256 多尺寸，安装程序与 exe 图标）。

macOS 的 `build/icon.icns` 需要另外生成（`png-to-ico` 只出 ico）：

```bash
node -e "const sharp=require('sharp'),fs=require('fs');const svg=fs.readFileSync('build/icon.svg');const T=[['icp4',16],['icp5',32],['icp6',64],['ic07',128],['ic08',256],['ic09',512],['ic10',1024],['ic11',32],['ic12',64],['ic13',256],['ic14',512]];(async()=>{const parts=[];for(const [t,s] of T){const png=await sharp(svg).resize(s,s).png().toBuffer();const h=Buffer.alloc(8);h.write(t,0,'ascii');h.writeUInt32BE(png.length+8,4);parts.push(h,png)}const body=Buffer.concat(parts);const head=Buffer.alloc(8);head.write('icns',0,'ascii');head.writeUInt32BE(body.length+8,4);fs.writeFileSync('build/icon.icns',Buffer.concat([head,body]))})()"
```

icns 就是「8 字节魔数 + 若干 `类型 + 长度 + PNG` 块」的容器格式，所以不需要 macOS 上的 `iconutil`，在 Windows 上纯 Node 拼出来一样能用。

### 改名与数据兼容

1.19.0 把应用标识从 `debug-toolbox` 改成 `flowprobe`（数据目录随之变化），1.21.4 进一步把显示名统一为英文 `FlowProbe`。前者牵动三处对老用户可见的东西，各自的处置如下。

| 受影响的东西 | 为什么会受影响 | 处置 |
| --- | --- | --- |
| 用户数据目录 | Electron 的 `userData` 目录名取自 `package.json` 的 `name`。改名后应用去找一个全新的空目录，表现就是「升级后会话、历史、证书全没了」 | 首次启动自动迁移（`src/main/userDataMigration.ts`）：把旧目录的 `workspace.json`、`update.json`、`history.db`（含 `-wal`/`-shm`）与 `certs/` **复制**到新目录，写一个哨兵文件避免重复搬 |
| 录制文件标识 | `.json` 录制文件里的 `format` 字段是加载准入条件，只认新值会让改名前导出的文件全部打不开 | 写入一律用 `flowprobe-recording`，读取同时接受旧的 `debug-toolbox-recording` |
| 安装包文件名 | 产物名由 `DebugToolbox-Setup-*.exe` 变成 `FlowProbe-Setup-*.exe`，而已发布的旧客户端是按 `latest.yml` 里记的名字去下载 | 改名这一版建议在 Release 里同时保留一份旧名副本，或直接通知用户手动装一次 |

关于迁移为什么是「复制」而不是「移动」：迁移出错或这一版被回退时，旧目录还在原地，用户可以装回旧版继续用。代价只是磁盘上多一份历史库，换来的是可逆。

迁移只搬上面列出的几项，Chromium 自己的 `Cache`、`GPUCache`、`Local Storage` 一概不搬——跨目录复制这些既慢又没有意义，它们会自动重建。

迁移是否发生过，看新数据目录下有没有 `.migrated-from-debug-toolbox` 文件，里面记了来源路径、时间与搬了哪几项。

### 打包常见问题

**Q：打包后打开历史记录报「数据库不可用」？**
A：`better-sqlite3` 是原生模块，必须在 `electron-builder.yml` 的 `asarUnpack` 里解包（`**/node_modules/better-sqlite3/**`），否则 asar 内的 `.node` 文件加载不了。新克隆仓库后先跑 `npx electron-builder install-app-deps`，为当前 Electron 版本重新编译原生模块。

**打包报 `ERR_ELECTRON_BUILDER_CANNOT_EXECUTE` 或文件被占用**
应用进程还在运行会锁住 `release/win-unpacked/` 中的文件。先结束进程再打包：

```powershell
Get-Process -Name 'FlowProbe' -ErrorAction SilentlyContinue | Stop-Process -Force
```

**运行时报 `Failed to load image ... build\icon.png`**
说明 `build/icon.png` 没被打进包。确认 `electron-builder.yml` 的 `files` 中包含 `build/icon.png`。

**串口打开失败 / 找不到原生模块**
确认 `asarUnpack` 包含 serialport 相关路径。electron-builder 会自动为 Electron 重编译 `@serialport/bindings-cpp`。

**首次打包卡在 winCodeSign 解压**
Windows 无符号链接权限所致。项目已关闭代码签名（`CSC_IDENTITY_AUTO_DISCOVERY=false`）。

#### 从 Windows 拷过来的项目：必须先跑 setup:mac

这是最容易卡住的一步。**如果你把整个项目文件夹（含 `node_modules`）从 Windows
拷到 mac，直接 `npm install` 是无效的**，npm 会输出 `up to date` 然后什么都不做。

原因：npm 只比对 `package-lock.json` 里的版本号与 `node_modules` 的实际版本，
**不校验二进制是哪个平台编译的**。于是留下两个隐患：

1. `node_modules/.bin/` 里仍是 Windows 的 `.cmd` / `.ps1`，并且丢失了 Unix 可执行位，
   于是报错：
   `sh: .../node_modules/.bin/electron-vite: Permission denied`
2. `better-sqlite3` 仍是 Windows 编译的 `.node`，即使绕过第 1 点，打包或启动时也会崩。

`npm run setup:mac` 就是为此准备的：它会删掉 `node_modules` 重装、按 Electron 的
ABI 重编原生模块、并兜底修复可执行位。

若不想用脚本，等价的手工步骤是：

```bash
rm -rf node_modules
npm install --foreground-scripts
npx electron-builder install-app-deps
chmod +x node_modules/.bin/*
```

#### 安装脚本被拦（npm 新版本）

若 `npm install` 出现类似提示：

```
npm warn install-scripts 5 packages have install scripts not yet covered by allowScripts
npm warn install-scripts   better-sqlite3@11.3.0 (install: node-gyp rebuild)
```

说明原生模块**压根没有被编译**。项目根目录的 `.npmrc` 已写入 `ignore-scripts=false`，
通常足够；若你的 npm 仍然拦截，按它给出的命令逐个放行：

```bash
npm install-scripts approve better-sqlite3
npm install-scripts approve @serialport/bindings-cpp
npm install-scripts approve electron
npm install-scripts approve esbuild
```

放行后重新执行 `npm run setup:mac`。

#### 首次打开提示「已损坏」或「无法验证开发者」

本项目没有 Apple 开发者证书，因此打包流程走的是 **ad-hoc 签名**（`scripts/adhoc-sign.cjs`）。
这一步是必需的而非可选：**Apple Silicon 的内核会直接杀掉签名无效的进程**，
不签名的 `.app` 双击后会立刻闪退。

ad-hoc 签名能让程序正常运行，但不能通过 Apple 公证（notarization），
所以首次打开仍需手动放行一次，二选一：

- 在 Finder 里 **右键点图标 → 打开**，弹窗里再点「打开」；
- 或到「系统设置 → 隐私与安全性」，找到被拦截的提示点「仍要打开」。

如果提示「已损坏，应移到废纸篓」，是 macOS 给下载文件加的隔离属性，执行：

```bash
xattr -dr com.apple.quarantine "/Applications/FlowProbe.app"
```

#### 打包 Linux

```yaml
linux:
  target: AppImage
  icon: build/icon.png
```

> 跨平台打包必须在目标系统上执行。原生模块（`better-sqlite3`、`serialport`）
> 需要按目标平台与 Electron 的 ABI 编译，Windows 上打不出可用的 mac 包。

## 六、安全设计

- 渲染进程开启 `contextIsolation`、关闭 `nodeIntegration`，仅通过 typed preload 暴露受控 API
- Mock 脚本运行在 Node `vm` 沙箱中，带执行超时限制，不暴露文件系统与网络能力
- 所有 IO 在主进程执行，异常隔离到会话级别，单会话故障不影响其他会话
- 请求体大小上限保护（HTTP Mock 默认 5MB），防止内存打爆
- 历史库只写本地用户数据目录，不做任何外发；SQL 全部参数化拼接，筛选条件不进字符串
- 自签证书与私钥落在用户数据目录的 `certs/`，私钥文件权限 `0600`，界面只展示指纹与有效期不展示私钥正文
